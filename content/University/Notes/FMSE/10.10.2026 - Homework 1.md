## Cheat sheet

> [!abstract] Concepts
> - **satisfiable**: there is an interpretation under which the formula is true
> - **valid** (tautology): the formula is true under every interpretation
> - **refutable**: there is an interpretation under which the formula is false
> - **unsatisfiable** (contradiction): the formula is false under every interpretation
> - **Φ valid ⟺ ¬Φ UNSAT**. This is the main trick: we check validity with a SAT solver.
> - Binding strength: `¬ > ∧ > ∨ > → , ↔ > ⊕`. Implication `→` associates to the right.
> - `p → q ≡ ¬p ∨ q`
> - De Morgan: `¬(p ∧ q) ≡ ¬p ∨ ¬q` and `¬(p ∨ q) ≡ ¬p ∧ ¬q`
> - CNF is a conjunction of clauses, and a clause is a disjunction of literals.
> - `∅ ∈ F`, i.e. F contains the empty clause, means **UNSAT**. `F = ∅`, i.e. no clauses, means **valid**.

> [!abstract] Resolution – intuition
> Take "It is winter or I ride my bike" `(z ∨ r)` and "It is not winter or I take the tram" `(¬z ∨ t)`.
> If z = 1, then t must hold. If z = 0, then r must hold. Either way `(r ∨ t)` holds.
> ```
> (C ∨ v)    (D ∨ ¬v)
> ───────────────────
>       (C ∨ D)
> ```
> - Resolution removes **one** variable at a time (the pivot).
> - Deriving the empty clause ⊥ proves that the clause set is UNSAT.
> - **Recipe for a validity proof:** negate the claim, convert to CNF, derive ⊥.

> [!abstract] BCP and DPLL
> **BCP (unit propagation)**: take a unit clause `(ℓ)`. Remove all clauses containing `ℓ`, and delete `¬ℓ` from the remaining ones. Repeat until a fixpoint or until the empty clause.
> **Pure literal**: the variable occurs only positively or only negatively. The clauses containing it can be removed.
> **DPLL**: run BCP. If the empty clause appeared, the result is UNSAT. If no clauses are left, the result is SAT. Otherwise guess a literal ℓ and call DPLL(F ∧ ℓ), and if that fails, call DPLL(F ∧ ¬ℓ).

> [!abstract] Tseitin and Plaisted-Greenbaum
> **Tseitin**: every connective gets a fresh variable tᵢ. Every `tᵢ ↔ (…)` is turned into clauses, and at the end we add a unit clause for the root.
> - `a ↔ (b ∧ c) ≡ (¬a ∨ b)(¬a ∨ c)(a ∨ ¬b ∨ ¬c)`
> - `a ↔ (b ∨ c) ≡ (¬a ∨ b ∨ c)(a ∨ ¬b)(a ∨ ¬c)`
> - `a ↔ ¬b ≡ (¬a ∨ ¬b)(a ∨ b)`
>
> The result is **equisatisfiable** with the original, and the size grows linearly.
>
> **Plaisted-Greenbaum**: instead of `↔` we keep only one direction. With polarity `+` (an even number of negations above the node) we write `tᵢ → …`, with polarity `−` we write `tᵢ ← …`.

- [x] Classify each formula as valid, satisfiable and refutable, or unsatisfiable: ✅ 2026-10-12
    - (a) `(a → b) → (¬a → ¬b)`
    - (b) `(a ∧ (a → b)) → b`

## C. Resolution

### C1
- [x] Can these clauses be resolved? If so, give the resolvent. ✅ 2026-10-13
    - (a) `(a ∨ b ∨ c)` and `(¬b ∨ c ∨ d)`
    - (b) `(a ∨ ¬b)` and `(a ∨ c)`
    - (c) `(¬a)` and `(a)`

> [!success]- Answer
> - (a) `(a ∨ c ∨ d)`. The literal c occurs in both clauses, so it appears once in the result.
> - (b) Not possible, there is no complementary pair.
> - (c) ⊥, the empty clause.

### C2
- [x] Show by resolution that the set `{(a ∨ b), (¬a ∨ c), (¬b ∨ c), (¬c)}` is UNSAT. ✅ 2026-10-13

> [!success]- Answer
> 1. `(¬a ∨ c)` + `(¬c)` gives `(¬a)`
> 2. `(¬b ∨ c)` + `(¬c)` gives `(¬b)`
> 3. `(a ∨ b)` + `(¬a)` gives `(b)`
> 4. `(b)` + `(¬b)` gives ⊥

### C3
- [x] Prove by resolution that `((a ∨ b) ∧ (a → c) ∧ (b → c)) → c` is valid. Compare the resulting CNF with task C2. ✅ 2026-10-13

> [!success]- Answer
> After negation you get `(a ∨ b) ∧ (¬a ∨ c) ∧ (¬b ∨ c) ∧ ¬c`, which is **exactly the same set as in C2**. A proof "by cases" is resolution.

### C4
- [x] "If it rains, it is wet. If it is wet, it is slippery. It is not slippery." Prove by resolution that it does not rain. ✅ 2026-10-13

> [!success]- Answer
> Clauses: `(¬p ∨ m)`, `(¬m ∨ s)`, `(¬s)`, plus the negated conclusion: `(p)`.
> 1. `p` + `(¬p ∨ m)` gives `m`
> 2. `m` + `(¬m ∨ s)` gives `s`
> 3. `s` + `¬s` gives ⊥

### C5
- [x] The set `(a ∨ b) ∧ (a ∨ ¬b) ∧ (¬a ∨ b) ∧ (¬a ∨ ¬b)` is UNSAT. Why can **unit resolution alone** (BCP) not show this? What follows from that? ✅ 2026-10-13

> [!success]- Answer
> There is no unit clause, so BCP cannot make a single step. Unit resolution is **not refutation complete**, which is why DPLL has to guess.

### D3
- [x] Run DPLL on `(a ∨ b) ∧ (a ∨ ¬b) ∧ (¬a ∨ c) ∧ (¬a ∨ ¬c ∨ d) ∧ (¬d ∨ ¬c)`. Start with the decision `a = 0` and draw the tree. ✅ 2026-10-13

> [!success]- Answer
> ```
>         /     \
>       ¬a       a
>        |       |
>        b       c
>        |       |
>       ⊥ (¬b)   d
>                |
>                ⊥ (¬d ∨ ¬c)
> ```
> Branch a=0: `(a ∨ b)` implies b, `(a ∨ ¬b)` implies ¬b, so there is a conflict.
> Branch a=1: c is implied, then d, and then `(¬d ∨ ¬c)` is falsified.
> Result: **UNSAT**.

## E. Encoding problems

### E1
- [x] You have three versions of the code: ✅ 2026-10-13
    - Original: `if (a) { if (b) f(); else g(); } else g();`
    - Version 2: `if (a && b) f(); else g();`
    - Version 3: `if (a || b) f(); else g();`

    Which "optimized" variant is correct? For the wrong one, give a counterexample. Which formula would you give to the solver?

> [!success]- Answer
> Version 2 is correct. Version 3 is wrong, counterexample: a=0, b=1, f=1, g=0. The original gives g=0, and version 3 gives f=1.
> You give the solver `encode(original) ⊕ encode(version)`. SAT means a bug, and the model is a counterexample. UNSAT means the versions are equivalent.

### E2
- [x] Can a triangle be colored with two colors? Let xᵢ mean that vertex i is red. Encode the condition "adjacent vertices have different colors" in CNF and show with DPLL that the result is UNSAT. ✅ 2026-10-13

> [!success]- Answer
> For every edge (i, j) you add `(xᵢ ∨ xⱼ) ∧ (¬xᵢ ∨ ¬xⱼ)`, 6 clauses in total.
> - x₁=1 forces ¬x₂ and ¬x₃, and then `(x₂ ∨ x₃)` is falsified.
> - x₁=0 forces x₂ and x₃, and then `(¬x₂ ∨ ¬x₃)` is falsified.
>
> Result: UNSAT. This is a general property: an odd cycle is not 2-colorable.
