Scores → weights: √dₖ, the mask and the softmax

One row of attention for the token at position i in “The small purple cow”. Raw scores qᵢ·kⱼ are scaled, masked (−∞ for j > i), then softmaxed. Try a large dₖ without scaling and watch the weights go one-hot and the gradient vanish.

largest weight
largest α(1−α), a proxy for gradient through softmax

Masked entries get e^(−∞) = 0, and the remaining weights still sum to 1. Scaling by a positive constant never changes the order.

RoPE: a turn says where the word stands

Pair i turns by θᵢ = b^(−2(i−1)/d) radians per position. The dials show the angle mθᵢ of a few pairs at position m. Fast pairs wrap around quickly (nearby order), slow pairs barely move (long distance).

Relative check

Query at m, key at m − 1: their angle difference for pair 1 is always θ₁ = 1 rad ≈ 57.3°, whatever m is. That is (R(m)q)ᵀ(R(n)k) = qᵀR(n−m)k.

YaRN: stretch the slow pairs only

Turns of each pair inside the training length. More than 32 turns: every angle seen, keep. Under 1 turn: unseen angles beyond the training length, divide by the scale. In between: blend.

Olmo 3 7B: b = 500,000, d = 128, 8K → 64K. The base and d come from the controls above.

The pilot's budget: C ≈ 6 · N · D

6 = 2 FLOPs forward + 4 backward (input gradient and weight gradient) per weight and token. N counts the parameters a token is multiplied with: in a MoE, the active ones.

Peak: 989 TFLOP/s × 3,600 s = 3.56 · 10¹⁸ FLOPs per H100-hour. Chinchilla: D ≈ 20N, so C ≈ 120N², N ≈ √(C/120).

KV cache: why long context costs memory

For every new token, only that token runs through the layers; its query meets every cached key, and its key and value are appended. Bytes per token = 2 (K and V) × layers × KV heads × head size × bytes per number.
